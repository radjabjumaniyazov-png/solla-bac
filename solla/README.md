# Solla — backend skeleton

## Запуск

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # при желании поменять SECRET_KEY
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000/docs — интерактивная документация (Swagger),
там можно вызвать все эндпоинты руками, не дожидаясь фронтенда.

## Что уже готово

- **Модели данных** (`app/models.py`) под все разделы ТЗ: users, contacts,
  blacklist, groups/group_members, channels/channel_subscribers, messages
  (универсальная таблица для чатов/групп/каналов).
- **Регистрация и логин** (`POST /auth/register`, `POST /auth/login`) —
  bcrypt-хеширование пароля, JWT-токен на час.
- **Профиль/настройки** (`app/routers/profile.py`) — смена имени, аватарки,
  пароля, юзернейма, управление чёрным списком. Покрывает вкладку 5 из ТЗ.
- **Контакты** (`app/routers/contacts.py`) — поиск по юзернейму, добавление,
  список, удаление. Покрывает вкладку 2 из ТЗ.

Проверка уникальности логина и юзернейма — на двух уровнях: в Pydantic-схеме
(формат) и в БД (UNIQUE-индекс + явная проверка перед вставкой), так что race
condition при одновременной регистрации тоже отловится (БД вернёт ошибку
целостности, если два запроса проскочат проверку одновременно — это стоит
обернуть в try/except IntegrityError, когда дойдём до нагрузочного тестирования).

## Что осталось (следующие шаги)

1. **Роутер групп** (`groups.py`) — создание, добавление/удаление участников,
   роли (owner/admin/member), покрывает вкладку 3.
2. **Роутер каналов** (`channels.py`) — создание, подписка, список
   рекомендованных (`is_recommended`), проверка прав на публикацию (только
   owner/admin канала может писать), покрывает вкладку 4.
3. **WebSocket-эндпоинт для сообщений** — реальный чат. REST здесь не подходит:
   нужно, чтобы сервер сам проталкивал новые сообщения подключённым клиентам,
   а не заставлял их поллить. Отдельно стоит продумать масштабирование (если
   будет больше одного инстанса сервера — понадобится Redis pub/sub, чтобы
   WebSocket-соединения на разных инстансах видели чужие сообщения).
4. **Загрузка файлов** (аватарки, вложения в чатах) — эндпоинт с
   `UploadFile`, хранение на диске или в S3-совместимом сторадже.
5. **Alembic** — как только схема БД начнёт меняться на реальных данных,
   `Base.metadata.create_all` перестанет годиться (он не умеет ALTER TABLE).
6. **Тесты** — pytest + httpx.AsyncClient, отдельная тестовая БД в памяти.
7. **Frontend**: экран логина/регистрации, затем 5 вкладок по ТЗ.

## Структура проекта

```
app/
  main.py           # точка входа, регистрация роутеров, CORS
  database.py        # подключение к SQLite/PostgreSQL
  models.py          # SQLAlchemy-модели
  schemas.py          # Pydantic-схемы запросов/ответов
  auth.py             # хеширование паролей, выдача и проверка JWT
  routers/
    auth.py           # /auth/register, /auth/login
    profile.py         # /profile/*
    contacts.py         # /contacts/*
```
